How this demo works

It is the real iFiNeX website code, unmodified, running in an iframe. Only one file is swapped: the database library.

🧩 A fake database in your browser

Key flows

How the pieces talk to each other.

🔐 Sign-in

Email→admin must have added it (app_users)→6-digit code by email→Supabase session→Hub

No passwords. If the email was not added you see “Not added yet — ask your admin”.

⚡ Realtime alerts

Alex saves→database trigger inserts bill_notifications→Realtime filter recipient_email = Priya→🔔 lights up

No refresh needed. Try “Admin tools” in the walkthroughs.

🗑️ Delete with a reason

Tap delete→reason required→delete_*_entry()→archive + notify

Nothing disappears silently; admins can read the history.

💾 Backup & restore

Backup file (.json)→validate→ifx_restore_rows ×200→only missing rows added

Restore never overwrites or deletes.

☁️ Google Drive

Connect→Google page→Edge function stores token→pg_cron runs schedule→file in hidden app folder

The app can only see its own folder, never the rest of your Drive.

🏠 Standalone mode

No server at all: everything stays on the device (and in backup files). Same screens; no sharing, no realtime. The Android app can run this way or connect to your Supabase project.

Run it yourself

The demo is only a showcase. The real thing runs on your own free accounts.

1 · Supabase

Create a free project, run supabase/schema.sql, add your first admin in app_users.

2 · Website

Put the web/ folder on GitHub Pages (or any static host) and put your project URL and public key in ifinex-config.json.

3 · Android

Open mobile/ in Android Studio, build the APK. Never put the service-role key in the web or app.

Full step-by-step guides are in the repository docs/ folder.

Honest limits of this demo

  • Fake backend: a stand-in reproduces what the database does for the screens (filters, realtime, notifications, delete-with-reason, squad functions, restore). It is not the real PostgreSQL, so real policy edge cases are not tested here.
  • Email codes, push alerts, scheduled jobs: not run. Sign-in is pre-done; push needs real keys; Drive schedules (pg_cron) only “run” when you press Back up.
  • Google Drive: the Google page is a clearly labelled simulation; the backup files live in memory.
  • Squad e-mail report needs a server function (send-report) that is not deployed in the standard project — it shows an error here.
  • Mobile app: it is the same web code inside an Android WebView; the demo shows it in a phone frame. Native extras (push registration, file save dialogs, in-app update) cannot run in a browser.
  • Data resets every time you reload.
